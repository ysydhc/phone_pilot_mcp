## 项目战略目标
- **主要价值：** 为客户端开发提供一个开箱即用的PC（Mac）控制手机设备的通道，可以无缝嵌入到开发流程中，节省开发者的重复工作。
- **架构原则：** 整体采用脚本+技能的架构，两者相互隔离，即可以通过脚本控制设备执行已封装好的重复任务，也可以通过技能命令直接控制设备执行某些任务。
- **非功能性需求：**
    - **性能：** 核心接口的95%响应时间 < 1000ms。
    - **安全性：** 所有用户数据在传输和存储时均需加密。

## 开发环境与工作流

### 环境设置
- **包管理器**: 使用 `uv` 进行依赖管理和虚拟环境创建。**禁止**使用 `pip install` 直接安装包。
- **环境变量**: 所有配置（如数据库连接、API密钥）必须通过环境变量管理。参考 `.env.example` 文件。**绝对禁止**在代码中硬编码敏感信息。
- **依赖管理**: 项目依赖在 `pyproject.toml` 中声明。添加新依赖后，请运行 `uv add <package_name>`。

### 核心命令
- **安装依赖**: `uv sync`
- **启动开发服务器**: `uv run python -m uvicorn app.main:app --reload --port 8000`
- **运行所有测试**: `uv run pytest`
- **运行特定测试**: `uv run pytest path/to/test_file.py::test_function_name -v`
- **代码风格检查与格式化**: 
  - 检查: `uv run ruff check .`
  - 自动修复: `uv run ruff check . --fix`
  - 格式化: `uv run ruff format .`

## 代码规范与设计原则

### 代码风格
- **类型提示**: 所有函数、方法参数和返回值**必须**有类型提示。使用 `mypy` 进行静态检查 (`uv run mypy .`)。
- **文档字符串**: 公共模块、类、函数及方法**必须**使用 **Google风格** 的文档字符串。
- **命名规范**: 
  - 变量/函数: `snake_case`
  - 类: `PascalCase`
  - 常量: `UPPER_SNAKE_CASE`
- **示例（好的代码）**:

"""
async def get_user_by_id(user_id: int, db_session: AsyncSession) -> User | None:
"""


### 设计约束
- **错误处理**: 使用自定义异常类，避免裸露的 `except:`。业务错误应提供清晰的错误消息和类型。
- **API设计**: 所有API响应必须使用Pydantic模型进行序列化。列表响应必须分页。
- **数据库交互**: 使用异步SQLModel进行所有数据库操作。禁止使用同步ORM或原始SQL字符串拼接。

## 测试策略

### 测试原则
- **测试位置**: 单元测试放在与被测代码同目录的 `tests/` 子目录下，文件名以 `test_` 开头。
- **测试数据库**: 测试必须使用独立的测试数据库（如SQLite内存数据库）。**严禁**污染开发或生产数据库。
- **测试覆盖**: 新功能或Bug修复必须包含相应的测试用例。核心业务逻辑要求覆盖率不低于90%。

## 协作与版本控制

### Git工作流
- **分支策略**: 功能开发使用 `feature/<简短描述>` 分支，Bug修复使用 `bugfix/<简短描述>` 分支。
- **提交信息**: 遵循Conventional Commits格式，例如：`feat: 添加用户登录API` 或 `fix(auth): 修复JWT令牌过期问题`。
- **Pull Request**: 在提交PR前，必须确保所有测试通过，并且代码通过了 `ruff` 和 `mypy` 检查。

## 安全边界与绝对禁忌

### 🚫 绝对禁止的操作
- **永远不要** 将任何形式的密钥、密码或 `.env` 文件提交到版本控制。
- **永远不要** 直接修改或删除数据库迁移文件（在 `alembic/versions/` 目录下）。
- **永远不要** 在未编写测试的情况下修改核心业务逻辑。
- **永远不要** 使用 `print` 语句记录日志，必须使用标准的 `logging` 模块。

### ⚠️ 需要人工确认的操作
- 添加新的**外部依赖**。
- 修改**数据库模式**（需要创建新的Alembic迁移脚本）。
- 更改**身份认证或授权**相关的逻辑。
