# Python 项目开发规范

## 1. 项目上下文与技术栈

*   **主要语言**: Python 3.8+
*   **代码风格**: 严格遵循 **PEP 8** 规范。
*   **依赖管理**: 使用 `pyproject.toml` 或 `requirements.txt` 明确声明依赖。
*   **类型提示**: 对所有函数、方法参数和返回值使用类型提示（Type Hints）。
*   **文档规范**: 模块、类、公共函数及方法必须使用 **Google 风格** 或 **NumPy 风格**的 docstring。

## 2. 代码风格与质量

### 编码规范
*   **命名**：变量和函数名使用 `snake_case`，类名使用 `PascalCase`，常量使用 `UPPER_SNAKE_CASE`。
*   **导入**：导入标准库、第三方库和本地模块之间应有空行，并按此顺序分组。禁止使用 `from module import *`。
*   **结构**：避免过长的函数（通常不超过50行）和过大的类。遵循单一职责原则。

### 错误处理
*   对可能失败的操作（如文件I/O、网络请求）使用 `try...except` 块，并捕获**具体的异常**。
*   禁止使用裸露的 `except:` 语句。
*   合理的错误日志记录。

## 3. 项目结构与架构

### 目录与模块
*   项目应具有清晰的模块化结构。可参考以下布局：

my_project/

├── src/                  # 源代码目录
│   ├── main_module/      # 主模块
│   │   ├── init.py
│   │   └── core.py
│   └── utils/            # 工具模块
│       ├── init.py
│       └── helpers.py
|       |__ android
            |__ adbCmd.py
├── tests/                # 测试目录
├── data/                 # 数据文件目录（可选）
├── docs/                 # 文档目录（可选）
├── pyproject.toml        # 项目配置与依赖
└── README.md             # 项目说明


*   脚本入口点应放在项目根目录或特定的 `scripts/` 目录下。

### 设计原则
*   **函数式与面向对象**：根据复杂度选择。简单任务用函数，复杂逻辑或有状态的用类。
*   **配置外部化**：将配置项（如API密钥、文件路径）抽离到环境变量或配置文件中（如 `.env`），**切勿硬编码在源码里**。

## 4. 测试与可维护性

### 测试要求
*   为新功能或修复的Bug编写单元测试，优先使用 `pytest`。
*   测试文件应与被测试模块同名，并加上 `test_` 前缀，存放于 `tests/` 目录。
*   核心业务逻辑的测试覆盖率应尽可能高。

### 可维护性
*   代码变更时，需同步更新相关的文档和测试。
*   生成代码后，应能通过 `python -m pylint` 或 `flake8` 等静态检查工具的基本检查。

## 5. 安全与最佳实践

*   **安全警告**：处理用户输入或外部数据时，必须防范注入攻击（如SQL注入、命令注入）。
*   **资源管理**：使用 `with` 语句管理文件、网络连接等资源，确保它们被正确关闭。
